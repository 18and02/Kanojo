# P4 实施计划

P4 目标是把长期记忆整理成可回看的“记忆名片” artifact,让系统不只会在对话中调用记忆,也能把关系、偏好、事件和反思沉淀为一张可检查、可导出的作品层。

## 里程碑

| 编号 | 交付 | 验收 |
| --- | --- | --- |
| P4.1 | 记忆名片视图 | 后端可生成确定性记忆名片;桌面端“记忆”页可查看和刷新 |
| P4.2 | 名片导出 | 可导出 Markdown / JSON,用于论文材料和演示留档 |
| P4.3 | 名片版本 | 重要节点生成快照,可对比关系与记忆变化 |
| P4.4 | 反思摘要 | 先用确定性规则把零散记忆压缩为可复核反思摘要,后续再接 LLM 润色 |

## 当前状态

- P4.1 已实现:
  - 后端新增 `GET /memory-card`;
  - 名片从 SQLite 的 active memories 确定性生成,不依赖 LLM;
  - 名片按 `relationship / preference / event / reflection` 分组;
  - 响应同时包含结构化 sections 和 Markdown artifact;
  - 桌面端“记忆”页新增记忆名片面板,支持刷新。
- P4.2 已实现:
  - 后端新增 `GET /memory-card/export?format=markdown|json`;
  - Markdown 导出返回 `text/markdown`,JSON 导出返回 UTF-8 JSON 文件;
  - 桌面端“记忆”页支持复制 Markdown、下载 Markdown 和下载 JSON。
- P4.3 已实现:
  - 后端新增 `memory_card_snapshots` 表;
  - 后端新增名片快照创建、列表、详情和与当前名片对比接口;
  - 对比结果按 `relationship / preference / event / reflection` 返回新增和移除项;
  - 桌面端“记忆”页新增版本视图,支持保存快照、刷新列表和对比当前变化。
- P4.4 已实现:
  - 后端新增 `GET /memory-card/reflection`;
  - 反思摘要从同一份记忆名片生成,返回样本就绪度、分组主题、证据、后续关注点和 Markdown;
  - 桌面端“记忆”页新增反思视图;
  - 记忆页内部导航优化为窄侧栏可读布局,避免新增页签后再次出现文字截断。

## P4.1 方案

P4.1 先做稳定、可复核的 artifact 视图:

- SQLite 仍是唯一真相源;
- 名片只读取 `memories` 与当前 session 的消息计数;
- 先按重要性、置信度和更新时间排序,每类展示少量高价值记忆;
- 后端返回结构化 JSON,同时生成 Markdown 字符串,为 P4.2 导出铺路;
- 桌面端只负责展示,不在前端重新拼装业务含义。

## P4.2 方案

P4.2 在 P4.1 的确定性名片之上补本地留档能力:

- 导出接口仍调用同一份 `memory_card()` 生成逻辑,避免展示内容和导出内容分叉;
- Markdown 用于论文材料、演示讲稿和人工检查;
- JSON 用于后续版本快照、自动评测和对比;
- 桌面端只触发复制/下载,不重新生成业务字段。

## P4.3 方案

P4.3 把当前态名片沉淀成可回看的版本快照:

- SQLite 新增 `memory_card_snapshots`,保存完整名片 JSON、Markdown、摘要、记忆数、消息数和创建时间;
- 快照内容来自同一份 `memory_card()` 生成逻辑,保证视图、导出和版本不分叉;
- 对比逻辑以 `kind + content` 作为稳定键,返回当前名片相对快照的新增、移除和不变数量;
- 桌面端“记忆”页拆成名片、命中、审计、版本四个内部视图,避免长名片把其他诊断信息挤到底部。

## P4.4 方案

P4.4 先交付稳定、可复核的反思摘要基线:

- 反思摘要仍从 SQLite active memories 派生,调用同一份 `memory_card()` 分组结果;
- 每个分组输出线索数、主题句、最多 3 条证据和下一步关注点;
- 样本就绪度用确定性规则判断:至少 4 条长期记忆且至少覆盖 2 个非空分组;
- 先不让 LLM 直接生成不可追溯描述,后续可在该结构化结果之上添加 LLM 润色层;
- 桌面端只展示后端返回结果,不重新拼装反思含义。

## 非目标

- P4 不做 LLM 自动润色,避免样本不足时生成不可复核描述;
- P4 不做自动定时快照,先保留手动关键节点快照;
- P4 不做分享发布和自动隐私脱敏,这些放到后续公开展示流程处理。
